## 1. HTTP 端点

### 1.1 当前已实现（Phase 1-2）

| 方法 | 路径 | 用途 | 请求体 | 响应 |
|-----|------|------|--------|------|
| POST | `/v1/messages` | Anthropic Messages 入口，支持 `stream: true` SSE | `AnthropicMessagesRequest` | non-streaming: `AnthropicMessagesResponse`（JSON）<br/>streaming: `text/event-stream` 逐帧输出 Anthropic SSE 事件 |
| GET  | `/dashboard/*` | Vite 构建产物静态挂载（`web/dist/`） | 无 | HTML / JS / CSS 静态资源；构建产物缺失时返回占位 HTML |
| GET  | `/healthz` | 健康检查 | 无 | `{"status": "ok"}` |

**入口协议细节**：

- `/v1/messages` 是网关的**唯一业务路径**。请求最小字段：`model` / `messages` / `max_tokens`（`src/gateway/validator.ts:validateMessagesRequest`）
- `mom_mode === 'always'` 时走 MoM 主链路（fanout advisor → concat references → aggregator）；否则原样透传到 provider
- Body 上限 10 MiB（`src/gateway/server.ts:BODY_LIMIT_BYTES`）
- 错误映射（`src/gateway/messages-handler.ts`）：
  - 400 → 请求体校验失败或 `ValidationError`（Anthropic error JSON: `invalid_request_error`）
  - Provider 原状态码 → `ProviderError`（透传 provider body，能 parse 就 parse）
  - 502 → 未分类的 `gateway_error`
  - Streaming 场景已开始 SSE 写入后遇错 → `event: error` 帧 + `end()`

**Provider 认证**（网关向 provider 发起时）：

- `PROVIDER_AUTH_STYLE=bearer` → `Authorization: Bearer <PROVIDER_API_KEY>`
- `PROVIDER_AUTH_STYLE=x-api-key` → `x-api-key: <PROVIDER_API_KEY>` + `anthropic-version: 2023-06-01`

### 1.2 已规划（Phase 4-6，尚未实现）

| 方法 | 路径 | 阶段 | 用途 |
|-----|------|------|------|
| GET  | `/api/traces?limit=100&offset=0` | Phase 4 | 分页返回 trace summary（不含全量 request/response，避免大 body） |
| GET  | `/api/traces/:id` | Phase 4 | 单条 trace 全量（含 advisor_results / aggregator_result / judge_result / baseline_result） |
| GET  | `/api/metrics?window=last_24h\|last_7d` | Phase 4 | 从 `traces` 表聚合，返回 `Metrics`（含 `total_usage` 分层：advisor / aggregator / judge）、成本 / 延迟 / cache 命中率 / `mom_trigger_rate` |
| GET  | `/api/config` | Phase 4 | 返回当前 `MoMConfig`（**不含 provider 秘钥**，只只读展示 `provider.base_url` / `provider.auth_style`） |
| POST | `/api/config` | Phase 4 | 保存 `MoMConfig`，原子写入 `data/mom.config.json`；触发 hot-reload 或提示重启（机制到 Phase 4 定） |
| GET  | `/api/comparison/:trace_id` | Phase 6 | 返回 `mom_result + baseline_result` 供前端并排展示 |

### 1.3 不会开放的路径

- **无 provider 秘钥编辑端点**：`PROVIDER_*` 只从 `.env` 读，Dashboard 只只读展示（decisions/002 拍板）
- **无 auth 端点**：MVP 假定本地运行、无认证；上线远期版本再加

## 2. 内部 MoM SDK 入口函数（`src/orchestrator/*` + `src/advisor/*` + `src/aggregator/*` + `src/cache/*` + `src/cost/*`）

以下函数是 MoM 业务逻辑的公共入口。**外部项目想复用 MoM 功能，只需要调这些函数、传 `RuntimeConfig` 与 `AnthropicMessagesRequest`**——零 Fastify 依赖（Phase 3 起）。

### 2.1 主调度入口

```ts
// src/orchestrator/orchestrator.ts
export interface Orchestrator {
  nonStreaming(
    body: AnthropicMessagesRequest,
    log: Logger,
  ): Promise<AnthropicMessagesResponse>;
  streaming(
    body: AnthropicMessagesRequest,
    output: NodeJS.WritableStream,
    log: Logger,
  ): Promise<void>;
}

createOrchestrator(runtime: RuntimeConfig): Orchestrator
```

**当前状态**：Phase 3 起完全解耦——`createOrchestrator` 工厂内部闭包持有 `FanoutCache`，返回 `nonStreaming` / `streaming` 两入口，接受最小 `Logger` 接口（`{info, warn, error}`）与 Node 标准 `NodeJS.WritableStream`。外部项目 import 时零 Fastify 依赖。

### 2.1.1 Trigger 判定

**当前状态**：Phase 3 起。纯函数、零依赖，纯粹的叙述性标签，不控制流程。

## 3. MoM 与网关消息处理解耦评估

### 3.1 当前耦合面（Phase 3 起已消除）

`git grep -n "FastifyReply\|FastifyRequest\|FastifyBaseLogger\|FastifyInstance" src/` 结果，业务层完全无 Fastify 依赖，仅剩 `src/gateway/*`（`server.ts` + `messages-handler.ts`）本身持有合理引用。原 3 处耦合已全部消除：

| 文件 | 原耦合点 | 现状（Phase 3） |
|---|---|---|
| `src/orchestrator/orchestrator.ts` | `orchestrate(body, reply, runtime, log)` 签名带 `FastifyReply` + `FastifyBaseLogger` | 改为 `createOrchestrator(runtime): { nonStreaming(body, log): Response; streaming(body, output, log): void }`；`Logger` 是最小 `{info, warn, error}` 接口 |
| `src/aggregator/aggregator-runtime.ts` | `runAggregatorStreaming(..., reply)` 参数含 `reply` | 改为 `output: NodeJS.WritableStream + { onEvent?, log? }` |
| `src/provider/stream-forward.ts` | `passthroughStream(req, reply, provider)` 内部 `reply.raw.setHeader` / `reply.hijack()` / `res.body.pipe(reply.raw)` | 改为 `passthroughStream(req, output: NodeJS.WritableStream, provider, { onEvent?, log? })`；SSE header + hijack 上移到 `messages-handler.ts` |

### 3.2 SDK 完整覆盖面（Phase 3 起 100%）

- 所有类型定义（`src/types/*`）— 零 Fastify 依赖
- 所有配置装配（`src/config*.ts`）— 零 Fastify 依赖
- Orchestrator + Advisor + Aggregator 全链路（`src/orchestrator/*` + `src/advisor/*` + `src/aggregator/*`）— 零 Fastify 依赖
- Cache + Cost（`src/cache/*` + `src/cost/*`）— 零 Fastify 依赖
- Provider 全部（`passthroughCall` + `passthroughStream`）— 零 Fastify 依赖
- 存储层（`src/storage/*`）— 零 Fastify 依赖

### 3.3 解耦后的使用姿态

外部项目复用 MoM 时：

```ts
import { getConfig } from '@mom/config';
import { createOrchestrator } from '@mom/orchestrator';

// 一次装配
const runtime = getConfig('/path/to/mom.config.json');
const orchestrator = createOrchestrator(runtime);

// non-streaming
const response = await orchestrator.nonStreaming(anthropicRequest, myLogger);

// streaming — 直接给一个 Node Writable，例如 http.ServerResponse
await orchestrator.streaming(anthropicRequest, res, myLogger);
```

- 不需要 Fastify
- 不需要 messages-handler.ts / server.ts / validator.ts
- 只依赖 undici（provider HTTP）+ node:sqlite（trace 落盘）+ node:crypto（cache key）

## 4. 类型契约

MoM SDK 对外暴露的核心类型都在 `src/types/mom.ts` 与 `src/types/anthropic.ts`：

- **Anthropic 协议类型**：`AnthropicMessagesRequest` / `AnthropicMessagesResponse` / `AnthropicMessage` / `ContentBlock` / `SystemBlock` / `Tool` / `Usage` / SSE 事件族
- **MoM 配置类型**：`ProviderConfig` / `MoMConfig` / `RuntimeConfig` / `AdvisorSettings` / `AggregatorSettings` / `CacheSettings` / `ComparisonSettings` / `ModelPricing`
- **MoM 运行时类型**：`AdvisorResult` / `AggregatorResult` / `JudgeResult` / `BaselineResult` / `Trace` / `Metrics` / `UsageBreakdown` / `FanoutCacheKey` / `FanoutCacheValue` / `TriggerReason`（Phase 3）
- **SDK 支撑类型**：`Logger` (`{info, warn, error}`)（Phase 3）、`FanoutCache` 接口（Phase 3）
- **默认值**：`DEFAULT_MOM_CONFIG`

外部项目复用时按需 `import type { ... } from '@mom/types'`。
