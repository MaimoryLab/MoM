**Phase 7 前端消费者补充**（无新增路由，`web/src/pages/PipelinePage.tsx` 起消费）：
- `GET /api/traces?limit=20&role=aggregator` → TurnSelect 下拉最近 20 个 gateway_request_id
- `GET /api/traces/by-gateway/:gateway_request_id` → 选中或 URL `?turn=<gwId>` 后加载 N+1 条上游 trace；`started_at / finished_at` 反演为时序动画节奏（前端 `web/src/lib/timing.ts:compressTimeline` 处理 >5s 等比压缩）；aggregator trace 的 `request_summary` + advisor trace 的 `response_summary` 组装 Diff Modal 内容

**入口协议细节**：

- `/v1/messages` 是网关的**唯一业务路径**。请求最小字段：`model` / `messages` / `max_tokens`（`src/gateway/validator.ts:validateMessagesRequest`）
- **`X-Session-ID` header**（可选）：eval / 客户端为每个逻辑任务生成一个 UUID，任务内所有请求携带同一 uuid；网关**只读 header**（不读 body.metadata），缺失即 `TraceRequest.session_id = null`；缺失时 `/trace/requests` 无法按该 session 查询
- `mom_mode === 'always'` 时走 MoM 主链路（fanout advisor → concat references → aggregator），落 N+1 条 TraceRequest（session_id + gateway_request_id 关联）；否则原样透传到 provider，落 1 条 role='passthrough' TraceRequest
- Body 上限 10 MiB（`src/gateway/server.ts:BODY_LIMIT_BYTES`）
- 错误映射（`src/gateway/messages-handler.ts`）：
  - 400 → 请求体校验失败或 `ValidationError`（Anthropic error JSON: `invalid_request_error`）
  - Provider 原状态码 → `ProviderError`（透传 provider body，能 parse 就 parse）
  - 502 → 未分类的 `gateway_error`
  - Streaming 场景已开始 SSE 写入后遇错 → `event: error` 帧 + `end()`
  - 各条错误路径都会落一条 `status='error'` 的 TraceRequest 后再抛给上层——保证 eval 侧能观察到失败

**Provider 认证**（网关向 provider 发起时）：

- `PROVIDER_AUTH_STYLE=bearer` → `Authorization: Bearer <PROVIDER_API_KEY>`
- `PROVIDER_AUTH_STYLE=x-api-key` → `x-api-key: <PROVIDER_API_KEY>` + `anthropic-version: 2023-06-01`

### 1.3 不会开放的路径

- **无 provider 秘钥编辑端点**：`PROVIDER_*` 只从 `.env` 读，Dashboard 只只读展示（decisions/002 拍板）
- **无 auth 端点**：MVP 假定本地运行、无认证；上线远期版本再加

### 1.4 `GET /trace/requests` 详细契约（ISS-011 / decision 006）

**查询参数**：

- `session_id`（必填）：UUID hex 8-4-4-4-12 格式（ISS-012 起放宽为 hex-only，正则 `^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$` 大小写不敏感）；接受 RFC 4122 v1-v8 / NIL / max UUID，eval 侧可采用 UUIDv7（timestamp-ordered）

**响应形态**：

```jsonc
// 200 OK
{
  "session_id": "0c2c668a-c3bf-4d78-8f00-000000000042",
  "requests": [ TraceRequest, ... ]   // 按 started_at 升序；空数组不是 404
}

// 400 invalid_request_error
{ "type": "error", "error": { "type": "invalid_request_error", "message": "..." } }

// 500 internal_error（存储层异常）
{ "type": "error", "error": { "type": "internal_error", "message": "..." } }
```

**`TraceRequest` 结构**（`src/types/mom.ts:TraceRequest`；一条 = 一次网关→provider 上游 HTTP 调用）：

```jsonc
{
  "request_id":          "uuid",                    // trace 自身 id
  "session_id":          "uuid" | null,             // X-Session-ID header 回显；缺失即 null
  "gateway_request_id":  "uuid",                    // 同一入口请求下 N+1 条 upstream 共享
  "role":                "advisor" | "aggregator" | "passthrough" | "baseline" | "judge",
  "client_model":        "modeless:auto",           // 客户端传进的原始 model
  "selected_model":      "paigod/pa/gpt-5.5",       // 实际转发到 provider 的模型
  "provider":            "apiproxy.paigod.work",    // 从 PROVIDER_BASE_URL host 派生
  "started_at":          1783741244243,             // epoch ms
  "finished_at":         1783741244305,             // epoch ms
  "duration_ms":         62,                        // 冗余 = finished_at - started_at
  "status":              "success" | "error" | "cache_hit",
  "usage": {

    "cache_read_tokens":    245600,                 // 命中缓存 prompt
    "cache_creation_tokens": 0,
    "output_tokens":        1889,
    "reasoning_tokens":     0                       // 上游若不报为 0
  },
  "pricing": {                                      // 请求时冻结的深拷贝；缺 pricing_table 条目时 null
    "currency":                 "CNY",              // 忠实来自 ModelPricing.currency；sync-pricing 脚本 `--currency` 默认 CNY，orchestrator 不做币种假设/汇率换算

    "cache_read_per_million":   2.0,                // null 表示无缓存折扣
    "cache_write_per_million":  10.0,               // sync-pricing 按 input × 1.25 估算（provider `/v1/models` 无此字段）
    "output_per_million":       28.0,
    "reasoning_per_million":    null,               // 项目暂无 reasoning 单价
    "source":                   "mom.config.json@2026-07-11T00:00:00.000Z"  // basename@<mtime iso>；stat 失败 fallback 到 basename
  },
  "error": {                                        // status='error' 时填，否则 null
    "type":        "provider_error" | "gateway_error" | "advisor_error" | "aggregator_error",
    "message":     "...",
    "http_status": 502 | null
  } | null,
  "request_summary": {
    "max_tokens":       4096,
    "temperature":      null,
    "stream":           false,
    "message_count":    1,
    "tool_use_count":   0
  },
  "response_summary": {                             // 缓存命中 / error 时 null
    "id":            "msg_...",
    "stop_reason":   "end_turn" | "max_tokens" | ... | null,
    "stop_sequence": null | "..."
  } | null,
  "trigger_reason":      "mom_off" | "fanout_cache_off" | "user_turn" | "skipped_tool_iteration"
                      | "tool_iteration_cache_miss" | "per_iteration" | "fanout_cache_hit",
  "cache_hit":           false,                     // 仅 advisor + cache 命中场景为 true
  "settings_snapshot":   MoMConfig                  // 请求瞬间的业务配置深拷贝（永不含 provider 秘钥）
}
```

**存储层职责**（`src/storage/traces.ts`）：

- `saveTraceRequest(trace)`：orchestrator 每次上游调用完成 / 失败后调用；抛错由上层 `log.error` 吞掉，不影响响应链路
- `getTraceRequestsBySessionId(session_id)`：SQL `WHERE session_id = ? ORDER BY started_at ASC`，命中索引 `idx_traces_session_id`
- `getTraceRequestById(request_id)` / `getRecentTraceRequests(limit)`：辅助 API

### 1.6 Dashboard `/api/*` 详细契约（Phase 4 / ISS-032 / decision 008）

**通用错误响应**：与 `/trace/requests` 一致 —— `{ type: 'error', error: { type, message } }`；`type` 枚举包含 `invalid_request_error` / `config_error` / `not_found` / `not_implemented` / `internal_error`。

#### GET /api/config

```jsonc
// 200 OK
{
  "mom": { /* MoMConfig 全量，永不含秘钥 */ },
  "provider": {
    "base_url": "https://api.example.com/v1",
    "auth_style": "bearer",
    "api_key_masked": "dee****yq"       // 固定 3+**** +2 形状，长度不泄漏
  },
  "mom_config_source": "mom.config.json@2026-07-14T08:00:00.000Z"
}
```

#### POST /api/config

请求体：`{ mom: MoMConfig }`，其他字段（包括 `provider`）被忽略。

生效流程：`assertMoMConfigShape` → `assertModeRequirements` → `saveMoMConfig(path, mom)` → `runtime.mom` 就地替换 → `runtime.mom_config_source` 用 `stampMoMConfigSource` 重算 → `orchestratorHolder.rebuild()`。

```jsonc
// 200 OK
{ "mom": MoMConfig, "mom_config_source": "mom.config.json@<new mtime iso>" }

// 400 invalid_request_error（shape 校验失败）
{ "type": "error", "error": { "type": "invalid_request_error", "message": "mom.pricing_table[\"model-x\"].cache_write must be a number" } }

// 400 config_error（assertModeRequirements 失败，例如 always + 空 slots）
{ "type": "error", "error": { "type": "config_error", "message": "mom_mode=\"always\" requires advisor.slots to be non-empty ..." } }

// 500 internal_error（saveMoMConfig 抛错）
{ "type": "error", "error": { "type": "internal_error", "message": "..." } }
```

#### GET /api/traces

**Query 参数**：
- `limit` 默认 100，上限 500
- `offset` 默认 0
- `role`（可选）`advisor` / `aggregator` / `passthrough`
- `status`（可选）`success` / `error` / `cache_hit`
- `gateway_request_id`（可选，直接命中 idx_traces_gateway_request_id 索引）

```jsonc
// 200 OK
{
  "items": [ TraceSummary, ... ],   // 按 started_at DESC，剥离 settings_snapshot / request_summary / response_summary
  "total": 1234,
  "limit": 100,
  "offset": 0
}

// 400 invalid_request_error（非法 role / status / limit / offset）
```

`TraceSummary` 字段清单：`request_id / session_id / gateway_request_id / role / client_model / selected_model / provider / started_at / finished_at / duration_ms / status / trigger_reason / cache_hit / usage / pricing / error`。**不含** `settings_snapshot` / `request_summary` / `response_summary`（列表页无需大 blob，前端要详情走 `/api/traces/:id`）。

#### GET /api/metrics

**Query 参数**：
- `window`（可选）`last_24h` / `last_7d` / `all`，默认 `all`
- `limit`（可选）`per_turn` 与 `timeline` 段的最大行数，默认 32，上限 500

```jsonc
// 200 OK
{
  "window": "all",
  "summary": {
    "request_count": 87,                 // COUNT(DISTINCT gateway_request_id)
    "mom_trigger_count": 62,             // ≠ mom_off
    "mom_trigger_rate": 0.7126,
    "avg_latency_ms": 3421.2,            // 入口请求耗时 = MAX(finished_at)-MIN(started_at) per gateway_request，再 AVG
    "total_cost_usd": 4.53,              // null 当至少一条 non-zero usage trace 缺 pricing 时
    "total_baseline_cost_usd": null,     // Phase 6 才有
    "cache_hit_rate": 0.34,              // advisor 层
    "total_usage": {
      "advisor":    { "input_tokens": 12000, "cache_read_tokens": 3400, "cache_creation_tokens": 800, "output_tokens": 6200, "reasoning_tokens": 0 },
      "aggregator": { ... },
      "judge":      { "input_tokens": 0, "cache_read_tokens": 0, "cache_creation_tokens": 0, "output_tokens": 0, "reasoning_tokens": 0 }
    }
  },
  "per_turn": [{
    "gateway_request_id": "<uuid>",
    "started_at": 1783741244243,
    "total_cost_usd": 0.041,             // 或 null（该 turn 有 non-zero usage 且缺 pricing）
    "advisor_cost_usd": 0.015,
    "aggregator_cost_usd": 0.026,
    "total_latency_ms": 4200,
    "trigger_reason": "user_turn"
  }],                                    // sorted DESC by started_at，取 limit 条
  "by_role": [{ "role": "advisor", "cost_usd": 0.62, "request_count": 245 }, ...],
  "cache_hit_by_model": [{
    "selected_model": "kimi-k2",
    "role": "advisor",
    "hit_count": 43,
    "total_count": 62,
    "rate": 0.6935
  }],
  "timeline": [{                         // 与 per_turn 同源，按 started_at ASC，取 limit 条
```

**成本 null 语义**：若一条 trace 有非零 `usage` 且缺 `pricing`（例如 pricing_table 里没配该模型），该聚合层的 `cost_usd` 返 `null`（"承认不知道"）；若所有相关 trace `usage` 都是零，`cost_usd` 返 `0`（"确实没花钱"）。

### 1.7 Live Compare 详细契约（Phase 6 / ISS-033，ISS-035 起改为异步 job）

#### POST /api/live/run

**请求体**：

```jsonc
{
  "prompt": "…",           // 非空字符串，长度 ≤ 32000
  "baseline_on": true,      // 是否并发发起 baseline call；false 时 judge 不跑
  "lang": "zh" | "en"      // 影响 judge prompt 与 baseline 语义（当前仅 judge prompt 分中英两版）
}
```

**响应**：`202 Accepted` + JSON `LiveRunSubmitResponse`：

```jsonc
{ "gateway_request_id": "<uuid>" }
```

- 服务器立即返回，MoM + baseline + judge 在后台 `queueMicrotask` 中异步跑；`comparisons` 表由 `createComparison` 在 202 之前同步插入，客户端可立刻 `GET /api/comparison/:gwId`
- 400 → 请求体校验失败（`{ type: "error", error: { type: "invalid_request_error", message } }`）
- ISS-035 起不再走 SSE；旧的 8-事件 `LiveRunEvent` union 已从 `dashboard-api.ts` 删除

```jsonc
    "scores":           { "mom": {…5维}, "baseline": {…5维} },
    "verdict_summary":  "…" | null,
    "fallback":         false
  } | null,
  "judge_error": { "message": "…" } | null
}

// 404 not_found
{ "type": "error", "error": { "type": "not_found", "message": "no comparison record for gateway_request_id=…" } }
```

- Judge scores 5 维固定为 `correctness / completeness / depth / clarity / usefulness`,整数 0–100
- `mom`/`baseline`/`judge` 字段独立为 null——一条 record 允许只有 mom 完成,前端可基于此渲染部分状态
- 3 个 `*_snapshot` 字段在 `createComparison` 时快照，与真实调用一致；老 comparison 行（ISS-035 之前写入）为 null，前端 fallback 显示 `unknown`
- `judge.fallback=true` 表示服务端走了正则抽 `{…}` 兜底路径,原始 `JSON.parse` 失败但结构对得上
- 全部失败(`parse_error=true`)时 judge 段仍为 null,`judge_error.message` 说明

#### GET /api/presets

```jsonc
// 200 OK
{
  "presets": [
    {
      "id": "binarySearch",
      "title_zh": "Rust 二分查找",
      "title_en": "Rust binary search",
      "zh": "<full zh prompt>",
      "en": "<full en prompt>"
    }

```

- 数据源 = `data/presets.json`（gitignore 白名单）
- 每次请求现读文件，允许运营 hot-swap 预设无需重启

- **`runJudgeCompare`**：一次 judge-compare 上游调用。内部随机匿名 A/B（`rand < 0.5` → MoM=A / Baseline=B，否则反之），拼接系统 prompt（中英各一）+ user message，调 `passthroughCall` 拿响应，走 `parseJudgeCompare`，parse 失败标 `parse_error=true` 且分数全 0。**永不 throw**——错误归入 `JudgeCompareResult.error`

### 3.1 当前耦合面（Phase 3 起已消除）

`git grep -n "FastifyReply\|FastifyRequest\|FastifyBaseLogger\|FastifyInstance" src/` 结果，业务层完全无 Fastify 依赖，仅剩 `src/gateway/*`（`server.ts` + `messages-handler.ts`）本身持有合理引用。原 3 处耦合已全部消除：

### 3.3 解耦后的使用姿态

外部项目复用 MoM 时：

```ts
import { getConfig } from '@mom/config';
```
