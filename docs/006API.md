## 1. HTTP 端点

### 1.1 当前已实现

| 方法 | 路径 | 用途 | 请求体 | 响应 |
|-----|------|------|--------|------|
| POST | `/v1/messages` | Anthropic Messages 入口，支持 `stream: true` SSE | `AnthropicMessagesRequest`；可选 header `X-Session-ID: <uuid>` | non-streaming: `AnthropicMessagesResponse`（JSON）<br/>streaming: `text/event-stream` 逐帧输出 Anthropic SSE 事件 |
| GET  | `/trace/requests?session_id=<uuid>` | Eval / dashboard 视角批量查询 trace（ISS-011） | 无 | `{ session_id, requests: TraceRequest[] }`，按 `started_at` 升序，空数组不 404 |
| GET  | `/dashboard/*` | Vite 构建产物静态挂载（`web/dist/`） | 无 | HTML / JS / CSS 静态资源；构建产物缺失时返回占位 HTML |
| GET  | `/healthz` | 健康检查 | 无 | `{"status": "ok"}` |

**入口协议细节**：

- `/v1/messages` 是网关的**唯一业务路径**。请求最小字段：`model` / `messages` / `max_tokens`（`src/gateway/validator.ts:validateMessagesRequest`）
- **`X-Session-ID` header**（可选）：eval / 客户端为每个逻辑任务生成一个 UUID，任务内所有请求携带同一 uuid；网关**只读 header**（不读 body.metadata），缺失即 `TraceRequest.session_id = null`；缺失时 `/trace/requests` 无法按该 session 查询
- `mom_mode === 'always'` 时走 MoM 主链路（fanout advisor → concat references → aggregator），落 N+1 条 TraceRequest（session_id + gateway_request_id 关联）；否则原样透传到 provider，落 1 条 role='passthrough' TraceRequest
- Body 上限 10 MiB（`src/gateway/server.ts:BODY_LIMIT_BYTES`）
- 错误映射（`src/gateway/messages-handler.ts`）：
  - 400 → 请求体校验失败或 `ValidationError`（Anthropic error JSON: `invalid_request_error`）
  - Provider 原状态码 → `ProviderError`（透传 provider body，能 parse 就 parse）
  - 502 → 未分类的 `gateway_error`
  - Streaming 场景已开始 SSE 写入后遇错 → `event: error` 帧 + `end()`
  - 各条错误路径都会落一条 `status='error'` 的 TraceRequest 后再抛给上层——保证 eval 侧能观察到失败

**Provider 认证**（网关向 provider 发起时）：

- `PROVIDER_AUTH_STYLE=bearer` → `Authorization: Bearer <PROVIDER_API_KEY>`
- `PROVIDER_AUTH_STYLE=x-api-key` → `x-api-key: <PROVIDER_API_KEY>` + `anthropic-version: 2023-06-01`

### 1.3 不会开放的路径

- **无 provider 秘钥编辑端点**：`PROVIDER_*` 只从 `.env` 读，Dashboard 只只读展示（decisions/002 拍板）
- **无 auth 端点**：MVP 假定本地运行、无认证；上线远期版本再加

### 1.4 `GET /trace/requests` 详细契约（ISS-011 / decision 006）

**查询参数**：

- `session_id`（必填）：UUID hex 8-4-4-4-12 格式（ISS-012 起放宽为 hex-only，正则 `^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$` 大小写不敏感）；接受 RFC 4122 v1-v8 / NIL / max UUID，eval 侧可采用 UUIDv7（timestamp-ordered）

**响应形态**：

```jsonc
// 200 OK
{
  "session_id": "0c2c668a-c3bf-4d78-8f00-000000000042",
  "requests": [ TraceRequest, ... ]   // 按 started_at 升序；空数组不是 404
}

// 400 invalid_request_error
{ "type": "error", "error": { "type": "invalid_request_error", "message": "..." } }

// 500 internal_error（存储层异常）
{ "type": "error", "error": { "type": "internal_error", "message": "..." } }
```

**`TraceRequest` 结构**（`src/types/mom.ts:TraceRequest`；一条 = 一次网关→provider 上游 HTTP 调用）：

```jsonc
{
  "request_id":          "uuid",                    // trace 自身 id
  "session_id":          "uuid" | null,             // X-Session-ID header 回显；缺失即 null
  "gateway_request_id":  "uuid",                    // 同一入口请求下 N+1 条 upstream 共享
  "role":                "advisor" | "aggregator" | "passthrough",
  "client_model":        "modeless:auto",           // 客户端传进的原始 model
  "selected_model":      "paigod/pa/gpt-5.5",       // 实际转发到 provider 的模型
  "provider":            "apiproxy.paigod.work",    // 从 PROVIDER_BASE_URL host 派生
  "started_at":          1783741244243,             // epoch ms
  "finished_at":         1783741244305,             // epoch ms
  "duration_ms":         62,                        // 冗余 = finished_at - started_at
  "status":              "success" | "error" | "cache_hit",
  "usage": {
    "input_tokens":         12034,
    "cache_read_tokens":    245600,                 // 命中缓存 prompt
    "cache_creation_tokens": 0,
    "output_tokens":        1889,
    "reasoning_tokens":     0                       // 上游若不报为 0
  },
  "pricing": {                                      // 请求时冻结的深拷贝；缺 pricing_table 条目时 null
    "currency":                 "CNY",              // 忠实来自 ModelPricing.currency；sync-pricing 脚本 `--currency` 默认 CNY，orchestrator 不做币种假设/汇率换算
    "input_per_million":        8.0,
    "cache_read_per_million":   2.0,                // null 表示无缓存折扣
    "cache_write_per_million":  10.0,               // sync-pricing 按 input × 1.25 估算（provider `/v1/models` 无此字段）
    "output_per_million":       28.0,
    "reasoning_per_million":    null,               // 项目暂无 reasoning 单价
    "source":                   "mom.config.json@2026-07-11T00:00:00.000Z"  // basename@<mtime iso>；stat 失败 fallback 到 basename
  },
  "error": {                                        // status='error' 时填，否则 null
    "type":        "provider_error" | "gateway_error" | "advisor_error" | "aggregator_error",
    "message":     "...",
    "http_status": 502 | null
  } | null,
  "request_summary": {
    "max_tokens":       4096,
    "temperature":      null,
    "stream":           false,
    "message_count":    1,
    "tool_use_count":   0
  },
  "response_summary": {                             // 缓存命中 / error 时 null
    "id":            "msg_...",
    "stop_reason":   "end_turn" | "max_tokens" | ... | null,
    "stop_sequence": null | "..."
  } | null,
  "trigger_reason":      "mom_off" | "fanout_cache_off" | "user_turn" | "skipped_tool_iteration"
                      | "tool_iteration_cache_miss" | "per_iteration" | "fanout_cache_hit",
  "cache_hit":           false,                     // 仅 advisor + cache 命中场景为 true
  "settings_snapshot":   MoMConfig                  // 请求瞬间的业务配置深拷贝（永不含 provider 秘钥）
}
```

**存储层职责**（`src/storage/traces.ts`）：

- `saveTraceRequest(trace)`：orchestrator 每次上游调用完成 / 失败后调用；抛错由上层 `log.error` 吞掉，不影响响应链路
- `getTraceRequestsBySessionId(session_id)`：SQL `WHERE session_id = ? ORDER BY started_at ASC`，命中索引 `idx_traces_session_id`
- `getTraceRequestById(request_id)` / `getRecentTraceRequests(limit)`：辅助 API

## 2. 内部 MoM SDK 入口函数（`src/orchestrator/*` + `src/advisor/*` + `src/aggregator/*` + `src/cache/*` + `src/cost/*`）

以下函数是 MoM 业务逻辑的公共入口。**外部项目想复用 MoM 功能，只需要调这些函数、传 `RuntimeConfig` 与 `AnthropicMessagesRequest`**——零 Fastify 依赖（Phase 3 起）。

### 2.1 主调度入口

```ts
// src/orchestrator/orchestrator.ts
export interface Orchestrator {
  nonStreaming(
    body: AnthropicMessagesRequest,
    sessionId: string | null,
    log: Logger,
  ): Promise<AnthropicMessagesResponse>;
  streaming(
    body: AnthropicMessagesRequest,
    sessionId: string | null,
    output: NodeJS.WritableStream,
    log: Logger,
  ): Promise<void>;
}

createOrchestrator(runtime: RuntimeConfig): Orchestrator
```

**当前状态**：ISS-009 起签名接受 `sessionId: string | null`（gateway 层从 `X-Session-ID` header 提取）。`createOrchestrator` 内部为每次入口请求生成 `gateway_request_id`，让 N+1 条上游 TraceRequest 通过 session_id + gateway_request_id 双键关联。工厂内部闭包持有 `FanoutCache`；返回值接受最小 `Logger` 接口（`{info, warn, error}`）与 Node 标准 `NodeJS.WritableStream`。外部项目 import 时零 Fastify 依赖。

## 3. MoM 与网关消息处理解耦评估

### 3.1 当前耦合面（Phase 3 起已消除）

`git grep -n "FastifyReply\|FastifyRequest\|FastifyBaseLogger\|FastifyInstance" src/` 结果，业务层完全无 Fastify 依赖，仅剩 `src/gateway/*`（`server.ts` + `messages-handler.ts`）本身持有合理引用。原 3 处耦合已全部消除：

| 文件 | 原耦合点 | 现状（Phase 3） |
|---|---|---|
| `src/orchestrator/orchestrator.ts` | `orchestrate(body, reply, runtime, log)` 签名带 `FastifyReply` + `FastifyBaseLogger` | 改为 `createOrchestrator(runtime): { nonStreaming(body, sessionId, log); streaming(body, sessionId, output, log) }`（ISS-009 起补 `sessionId: string \| null`）；`Logger` 是最小 `{info, warn, error}` 接口 |
| `src/aggregator/aggregator-runtime.ts` | `runAggregatorStreaming(..., reply)` 参数含 `reply` | 改为 `output: NodeJS.WritableStream + { onEvent?, log? }` |
| `src/provider/stream-forward.ts` | `passthroughStream(req, reply, provider)` 内部 `reply.raw.setHeader` / `reply.hijack()` / `res.body.pipe(reply.raw)` | 改为 `passthroughStream(req, output: NodeJS.WritableStream, provider, { onEvent?, log? })`；SSE header + hijack 上移到 `messages-handler.ts` |

### 3.2 SDK 完整覆盖面（Phase 3 起 100%）

- 所有类型定义（`src/types/*`）— 零 Fastify 依赖
- 所有配置装配（`src/config*.ts`）— 零 Fastify 依赖
- Orchestrator + Advisor + Aggregator 全链路（`src/orchestrator/*` + `src/advisor/*` + `src/aggregator/*`）— 零 Fastify 依赖
- Cache + Cost（`src/cache/*` + `src/cost/*`）— 零 Fastify 依赖
- Provider 全部（`passthroughCall` + `passthroughStream`）— 零 Fastify 依赖
- 存储层（`src/storage/*`）— 零 Fastify 依赖

### 3.3 解耦后的使用姿态

外部项目复用 MoM 时：

```ts
import { getConfig } from '@mom/config';
import { createOrchestrator } from '@mom/orchestrator';

// 一次装配
const runtime = getConfig('/path/to/mom.config.json');
const orchestrator = createOrchestrator(runtime);

// non-streaming（sessionId 可为 null；有则用于按 session 聚合 trace）
const sessionId = req.headers['x-session-id'] ?? null;
const response = await orchestrator.nonStreaming(anthropicRequest, sessionId, myLogger);

// streaming — 直接给一个 Node Writable，例如 http.ServerResponse
await orchestrator.streaming(anthropicRequest, sessionId, res, myLogger);
```

- 不需要 Fastify
- 不需要 messages-handler.ts / server.ts / validator.ts
- 只依赖 undici（provider HTTP）+ node:sqlite（trace 落盘）+ node:crypto（cache key）

## 4. 类型契约

MoM SDK 对外暴露的核心类型都在 `src/types/mom.ts` 与 `src/types/anthropic.ts`：

- **Anthropic 协议类型**：`AnthropicMessagesRequest` / `AnthropicMessagesResponse` / `AnthropicMessage` / `ContentBlock` / `SystemBlock` / `Tool` / `Usage` / SSE 事件族
- **MoM 配置类型**：`ProviderConfig` / `MoMConfig` / `RuntimeConfig` / `AdvisorSettings` / `AggregatorSettings` / `CacheSettings` / `ComparisonSettings` / `ModelPricing`
- **MoM 运行时类型**：`AdvisorResult` / `AggregatorResult` / `JudgeResult` / `BaselineResult` / `TraceRequest`（ISS-009 起替代旧 `Trace`）/ `TraceUsage` / `PricingSnapshot` / `TraceError` / `TraceErrorType`（ISS-012 起收窄为 union）/ `RequestSummary` / `ResponseSummary` / `Metrics` / `UsageBreakdown` / `FanoutCacheKey` / `FanoutCacheValue` / `TriggerReason`（Phase 3）
- **`RuntimeConfig`**（ISS-012 起）：新增 `mom_config_source: string` 字段，`getConfig` 时读 `mom.config.json` mtime 拼 `basename@<iso>`，orchestrator 用其替代常量作为 `TraceRequest.pricing.source`
- **SDK 支撑类型**：`Logger` (`{info, warn, error}`)（Phase 3）、`FanoutCache` 接口（Phase 3）
- **默认值**：`DEFAULT_MOM_CONFIG`

外部项目复用时按需 `import type { ... } from '@mom/types'`。
